# 03 — Справочник типов нод

9 типов. UI-лейбл — как называется тип в выпадающем списке «Тип узла» в редакторе.

| `type` | UI-лейбл | Ждёт ввод? | `transitions`? |
|---|---|---|---|
| `start` | Начало | нет | да (точка входа) |
| `message` | Сообщение | да (если есть regex-переходы) | да |
| `condition` | Условие | нет | **нет** (`trueTarget`/`falseTarget`) |
| `action` | Действие | нет | да (обычно `unconditional`) |
| `http` | HTTP запрос | нет | да (обычно `unconditional`) |
| `notify_user` | Уведомление в ЛС | нет | да (обычно `unconditional`) |
| `schedule_message` | Отложенное сообщение | нет | да (обычно `unconditional`) |
| `clear_scheduled_messages` | Очистить очередь | нет | да (обычно `unconditional`) |
| `end` | Конец | — | нет |

---

## `start` — Начало
Точка входа. Обычно один переход на первый содержательный узел.
```json
"start": {
  "type": "start",
  "transitions": [
    { "id": "to-welcome", "regex": ".*", "priority": 0,
      "description": "Старт", "targetNodeId": "welcome", "unconditional": true }
  ]
}
```

## `message` — Сообщение
Основной узел: отправляет текст (+ опц. клавиатуру/вложения) и, если есть regex-переходы,
ждёт ответ пользователя.

Поля `data`:
| Поле | Тип | Назначение |
|---|---|---|
| `message` | string | Текст. Поддерживает `{varName}`. |
| `keyboard` | object | Клавиатура `reply` или `inline` (см. ниже). |
| `saveVariable` | string | Имя переменной в `context`, куда сохранить ответ пользователя. |
| `enableErrorHandling` | bool | Включить обработку невалидного ввода (в новых узлах ставь `true`). |
| `invalidInputMessage` | string | Что ответить, если ни один regex не подошёл. |
| `maxInvalidAttempts` | number | Сколько невалидных попыток до перевода в fallback-узел. |
| `invalidAttemptsTargetNodeId` | string | Куда перевести после превышения лимита попыток. |

```json
"welcome": {
  "type": "message",
  "data": {
    "message": "Привет, {user_name}! Выберите действие:",
    "keyboard": {
      "type": "reply", "resize_keyboard": true, "one_time": false,
      "buttons": [
        [{ "text": "Оставить заявку" }, { "text": "Узнать цены" }],
        [{ "text": "Связаться с менеджером" }]
      ]
    },
    "saveVariable": "user_choice",
    "enableErrorHandling": true,
    "invalidInputMessage": "Я вас не понял, выберите пункт меню.",
    "maxInvalidAttempts": 3,
    "invalidAttemptsTargetNodeId": "main_menu"
  },
  "transitions": [
    { "id": "go-lead",  "regex": "/Оставить заявку/i", "priority": 1, "description": "Лид",      "targetNodeId": "collect_name" },
    { "id": "go-price", "regex": "/Узнать цены/i",      "priority": 2, "description": "Прайс",    "targetNodeId": "prices" },
    { "id": "fallback", "regex": ".*",                  "priority": 100,"description": "Повтор",  "targetNodeId": "welcome" }
  ]
}
```

### Клавиатуры (поле `data.keyboard`, не отдельный тип)
- **`reply`** — кнопки под полем ввода. При нажатии отправляется их текст.
  Тексты кнопок **должны зеркалиться в `regex` переходов**. Для коротких известных ответов
  («Да», «Нет», «Тарифы»), меню, квизов.
  Кнопка: `{ "text": "Да" }`.
- **`inline`** — кнопки внутри сообщения. Нужны для `callback_data`, `url`, `web_app`.
  Кнопка: `{ "text": "Подробнее", "callback_data": "more_info" }` или `{ "text": "Сайт", "url": "https://..." }`.
- `buttons` — массив рядов, каждый ряд — массив кнопок.

## `condition` — Условие
Ветвление по JS-выражению над `context`. **Нет `transitions`.**

Поля `data`:
| Поле | Тип | Назначение |
|---|---|---|
| `condition` | string | JS-выражение, выполняется как `new Function('context','return '+condition)`. |
| `trueTarget` | string | Узел при `true`. |
| `falseTarget` | string | Узел при `false`. |

```json
"result": {
  "type": "condition",
  "data": {
    "condition": "context.user_choice && context.user_choice.includes('цены')",
    "trueTarget": "prices",
    "falseTarget": "thanks"
  }
}
```
✅ `"parseInt(context.nps_score) >= 9"` ❌ `"{nps_score} >= 9"` (в условиях `{}` НЕ работает).

## `action` — Действие
Записать значение в переменную `context` (служебная логика). Используется редко —
для сохранения ответа пользователя достаточно `saveVariable` в `message`.
После — обычно безусловный переход.

## `http` — HTTP запрос
Внешний запрос (интеграции). Получает JSON и маппит поля в переменные.

Поля `data`:
| Поле | Тип | Назначение |
|---|---|---|
| `url` | string | URL. Поддерживает `{varName}`. |
| `method` | string | `GET`/`POST`/... |
| `headers` | object | Заголовки. |
| `body` | string/object | Тело (для POST). Поддерживает `{varName}`. |
| `variableMappings` | array | `[{ "field": "data.plan", "variable": "plan_name" }]` — путь в JSON-ответе → имя переменной. |

```json
"prices": {
  "type": "http",
  "data": {
    "url": "https://api.example.com/prices?name={lead_name}",
    "method": "GET",
    "headers": { "Content-Type": "application/json" },
    "variableMappings": [{ "field": "data.plan", "variable": "plan_name" }]
  },
  "transitions": [
    { "id": "after-http", "regex": ".*", "priority": 0, "unconditional": true,
      "description": "После HTTP", "targetNodeId": "thanks" }
  ]
}
```

## `notify_user` — Уведомление в ЛС
Отправляет сообщение в личку по `recipientId` (в том же канале, где идёт диалог). Для
алертов менеджеру/складу: собрал данные → уведомил ответственного.

Поля `data`:
| Поле | Тип | Назначение |
|---|---|---|
| `recipientId` | string | ID получателя. Поддерживает `{varName}` (напр. `{manager_id}`). |
| `message` | string | Текст. Поддерживает `{varName}`. |

После узла обычно ставят безусловный переход для продолжения сценария.
```json
"notify_manager": {
  "type": "notify_user",
  "data": {
    "recipientId": "{manager_id}",
    "message": "Новая заявка от {lead_name}. Выбор: {user_choice}"
  },
  "transitions": [
    { "id": "after-notify", "regex": ".*", "priority": 0, "unconditional": true,
      "description": "Продолжить", "targetNodeId": "result" }
  ]
}
```

## `schedule_message` — Отложенное сообщение
Отправляет сообщение с задержкой после попадания в узел (напоминания, follow-up).

Поля `data`:
| Поле | Тип | Назначение |
|---|---|---|
| `delayValue` | number | Величина задержки. |
| `delayUnit` | string | Единица: `minutes`, `hours`, `days`, ... |
| `message` | string | Текст (поддерживает `{varName}`). |
| `keyboard` | object | Опц. клавиатура (reply/inline). |

```json
"thanks": {
  "type": "schedule_message",
  "data": {
    "delayValue": 30, "delayUnit": "minutes",
    "message": "Спасибо! Если остались вопросы, ответьте на это сообщение.",
    "keyboard": { "type": "inline", "buttons": [[{ "text": "Открыть сайт", "url": "https://example.com" }]] }
  },
  "transitions": [
    { "id": "to-end", "regex": ".*", "priority": 0, "unconditional": true,
      "description": "Завершить", "targetNodeId": "finish" }
  ]
}
```
> Примечание: на момент записи отложка работает по **задержке** (delay), а не по конкретной
> дате/времени; разработчик планировал добавить запуск на конкретную дату.

## `clear_scheduled_messages` — Очистить очередь
Чистит стек отложенных сообщений (чтобы пользователю не пришла пачка дублей при повторных
попаданиях в узел-напоминание). Ставится перед новым напоминанием/в конце.
```json
"finish": {
  "type": "clear_scheduled_messages",
  "transitions": [
    { "id": "end", "regex": ".*", "priority": 0, "unconditional": true,
      "description": "В end", "targetNodeId": "end_node" }
  ]
}
```

## `end` — Конец
Завершение ветки. Без `transitions`. Поведение после `end` зависит от флага **Цикличность**
сценария (см. [01](01-Обзор-и-разделы.md)).
```json
"end_node": { "type": "end" }
```
