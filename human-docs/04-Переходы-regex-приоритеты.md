# 04 — Переходы, regex, приоритеты

## Как движок выбирает переход

После того как пользователь прислал сообщение, движок берёт переходы текущего узла и
проверяет их **по возрастанию `priority`** (меньше число = выше приоритет):

1. Сортирует переходы по `priority` (0, 1, 2, … 50, … 100).
2. Идёт сверху вниз и берёт **первый**, чей `regex` совпал с сообщением.
3. Переходит в его `targetNodeId`.
4. Если сообщение совпадает с несколькими regex — выигрывает тот, у кого **меньше `priority`**.
5. Если не совпал ни один — срабатывает обработка невалидного ввода (см. ниже) или, если
   есть, fallback-переход с `".*"`.

**Практика приоритетов:**
- конкретные осмысленные переходы: `priority` 1–10;
- общий fallback `"regex": ".*"`: `priority >= 100` (ловит всё, что не распознано).

## regex — это JavaScript RegExp

Движок исполняет regex как нативный `RegExp` JS. Пиши в форме `/паттерн/флаги`.

✅ Правильно:
```
"regex": "/да|интересно/i"
"regex": "/^[\w.-]+@[\w.-]+\.[a-z]{2,}$/i"
"regex": ".*"
```

❌ Неправильно (ломает сценарий):
```
"regex": "(?i)(да|нет)"      // инлайновые флаги (?i) НЕ поддерживаются
"regex": "(?i)привет"
```

Подсказки:
- `i` — регистронезависимость (почти всегда нужна для текста кнопок/команд).
- Для reply-кнопок **зеркаль текст кнопки в regex**: кнопка `"Узнать цены"` → `"/Узнать цены/i"`.
- `".*"` матчит любое сообщение — используй только как fallback с высоким `priority`.

## Безусловные переходы (`unconditional: true`)

Выполняются **сразу**, не дожидаясь ответа пользователя. Нужны, чтобы:
- отправить несколько сообщений подряд (цепочка `message` через `unconditional`);
- продолжить сценарий после служебных узлов (`action`, `http`, `notify_user`,
  `schedule_message`, `clear_scheduled_messages`).

Цепочка безусловных узлов «пробегается» мгновенно до первого узла, который ждёт ввод
(`message` с regex-переходами) — там бот останавливается и ждёт пользователя.

## Обработка невалидного ввода (узлы `message`)

Поля в `data` узла `message`, который ждёт ответ:
- `enableErrorHandling: true` — включает логику.
- `invalidInputMessage` — текст при несовпадении со всеми regex.
- `maxInvalidAttempts` — лимит невалидных попыток.
- `invalidAttemptsTargetNodeId` — куда увести после превышения лимита.

Правила:
- если ни один regex не подошёл → бот шлёт `invalidInputMessage`;
- каждый невалидный ответ увеличивает счётчик;
- при превышении `maxInvalidAttempts` → бот шлёт `invalidInputMessage` и переводит в
  `invalidAttemptsTargetNodeId`;
- если `maxInvalidAttempts` не задан → бот просто повторяет `invalidInputMessage` без перевода;
- в новых/изменённых узлах **всегда** ставь `enableErrorHandling: true` (старые узлы без него
  могут не иметь этой логики — обратная совместимость).
