# 06 — Генерация сценариев через LLM

Главный рабочий процесс продукта: **нейросеть генерирует JSON-сценарий → импорт в редактор.**
Руками собирать сценарий из десятков нод долго; цель — генерить и потом точечно править.

## Встроенные промпты (`/prompts`)

10 готовых шаблонов по нишам:
Интернет-магазин · FAQ/Техподдержка · Генерация лидов · Запись на приём · Ресторан/Доставка ·
Опрос/NPS · HR-скрининг · Онбординг/Обучение · Универсальный ассистент.

Каждый шаблон состоит из 3 частей:
1. **Сценарий** — что должен делать бот (нумерованные требования).
2. **Параметры вашего бизнеса** — синяя редактируемая часть (заполняешь под клиента).
3. **Требования к выводу** — сколько узлов, какая структура, какие узлы обязательны.

Кнопки:
- **Копировать** — копирует только текст сценария.
- **Показать контекст платформы и JSON-схему** — раскрывает спецификацию платформы.
- **Скопировать полный промпт** — копирует **всё вместе**: спецификация платформы +
  сценарий + бизнес-контекст + требования к выводу. Это и есть готовый промпт для LLM.

## Как использовать (по шагам)

1. На `/prompts` выбери нишу, заполни «синюю» часть под конкретный бизнес.
2. Нажми **«Скопировать полный промпт»**.
3. Вставь в ChatGPT / Claude / любую LLM.
4. Получи на выходе **только JSON** (промпт требует «Верни ТОЛЬКО валидный JSON без пояснений»).
5. Импортируй JSON в продукт (см. ниже).

## Как загрузить JSON в продукт

- **Импорт (файл):** страница «Боты» → кнопка **Импорт** → выбрать `.json` файл → бот появится
  в списке, сразу доступен для редактирования.
- **JSON-редактор (вставка):** Редактор → **JSON редактор** → вставить JSON в Monaco →
  **Форматировать** (проверить «✓ JSON валиден») → **Сохранить**.

## Как доработать существующий сценарий через LLM

1. На странице «Боты» у нужного бота → **Экспорт** (скачивается JSON).
2. Скорми этот JSON нейросети **вместе со спецификацией платформы** (промпт/скилл должен быть
   в контексте) и опиши правки («добавь опросник», «добавь ветку отказа» и т.п.).
3. Получи обновлённый JSON → **Импорт** обратно (или вставь в JSON-редактор и сохрани).

## Чек-лист валидного сгенерированного сценария

- [ ] Есть узлы `start` и `end`.
- [ ] Все `targetNodeId` / `trueTarget` / `falseTarget` / `invalidAttemptsTargetNodeId`
      ссылаются на существующие ключи в `states`.
- [ ] `condition`-узлы без `transitions`, только `trueTarget`/`falseTarget`.
- [ ] regex в форме `/.../i`, без `(?i)`.
- [ ] Конкретные переходы `priority` 1–10, fallback `".*"` → `priority >= 100`.
- [ ] В условиях — `context.varName`, в текстах — `{varName}`.
- [ ] Все используемые переменные объявлены в `config.context`.
- [ ] На узлах, ждущих ввод, проставлен `enableErrorHandling: true` + fallback.
- [ ] После служебных узлов (`http`, `notify_user`, `action`, `schedule_message`,
      `clear_scheduled_messages`) стоит `unconditional: true` переход.
- [ ] Только разрешённые 9 типов узлов.

## Контекст про «скиллы» и ИИ-агента (из записи встречи)

- У разработчика в Obsidian есть **скиллы** с описанием типов блоков для нейросети
  (примеры правильные/неправильные). По его словам, результат из этих скиллов — лучше, чем из
  встроенной страницы промптов.
- Цель команды — **ИИ-агент, который пишет сценарии на демке**: на выходе — итоговый JSON,
  импортируемый в продукт. Под это и собирается данная база знаний (много `.md`).
- Источник истины для генерации — спецификация в
  [canonical/platform-spec.md](canonical/platform-spec.md). Держи её в контексте LLM.
