# 08 — Эксплуатация: аналитика, диалоги, логи

## Аналитика (`/analytics`)

Статистика по сценарию. Собирается **только по узлам, у которых включён флаг «Аналитика»**
(переключатель «В статистике / Не в статистике» на вкладке «Основные» свойств узла).
Полезно для опросников/квизов: смотреть, как распределяются ответы пользователей по узлу.
Если ботов нет — «Нет доступных ботов для аналитики».

> Совет генерации: для узлов-вопросов, где важна аналитика ответов (NPS, опрос, квиз),
> имеет смысл включать флаг статистики.

## Диалоги (`/dialogs`)

Журнал сессий пользователей. Используется для разбора/дебага пути человека.

**Фильтры:** Бот · Период · Статус · Сортировка (по дате начала).

**Колонки таблицы:**
| Колонка | Что показывает |
|---|---|
| ID Сессии | `session_…`, `telegram_…` и т.п. |
| Бот | id бота. |
| Дата начала / окончания | «Активна», если сессия не завершена. |
| Сообщений | счётчик сообщений в сессии. |
| Длительность | сколько длится/длилась. |
| **Состояние** | **текущая нода**, на которой «припаркован» пользователь (`main_menu`, `collect_name`, `hub_pause`, `registration_confirmed`, …). |
| Действия | **Детали**, **Логи юзера**. |

Колонка «Состояние» = `state` из машины состояний → прямо видно, на каком узле сценария
застрял/находится каждый пользователь. Очень удобно для отладки сценария.

## Логи пользователей (`/user-logs`)

Подробный лог событий конкретного пользователя/сессии. Открывается из диалога кнопкой
**«Логи юзера»** (прямой заход на `/user-logs` без выбранной сессии редиректит на `/dialogs`).
Нужен, когда надо детально «задебажить» путь конкретного пользователя по сценарию.

## Типовой цикл отладки

1. Пользователь жалуется / сценарий ведёт себя не так.
2. `/dialogs` → найти сессию → посмотреть колонку **Состояние** (где застрял).
3. **Детали / Логи юзера** → проследить, какие сообщения и переходы сработали.
4. Поправить сценарий в редакторе (regex/приоритеты/переходы/цикличность) → сохранить.
5. Проверить в предпросмотре и на реальном канале.
