# 09 — Шпаргалка и частые ошибки

## Мини-шпаргалка по нодам

```
start                    → точка входа, 1 переход на welcome (часто unconditional)
message                  → текст + keyboard + saveVariable + обработка ошибок + transitions(regex)
condition                → JS над context; trueTarget/falseTarget; БЕЗ transitions
action                   → записать переменную (редко); затем unconditional
http                     → url/method/headers/body + variableMappings; затем unconditional
notify_user              → recipientId + message (в ЛС); затем unconditional
schedule_message         → delayValue + delayUnit + message (+keyboard); отложенная отправка
clear_scheduled_messages → очистить очередь отложенных; затем unconditional
end                      → конец ветки (поведение зависит от «Цикличность»)
```

## Подстановка vs условие

```
В тексте/URL/notify:   {varName}
В condition (JS):       context.varName
```

## regex

```
✅ "/да|нет/i"      ✅ ".*"      ✅ "/^[\w.-]+@[\w.-]+\.[a-z]{2,}$/i"
❌ "(?i)да"         ❌ "(?i)привет"
```

## Приоритеты

```
конкретные переходы:  priority 1..10
fallback ".*":        priority >= 100
меньше число = выше приоритет; проверка по возрастанию, берётся первый совпавший
```

## Топ ошибок при генерации (избегать)

1. **`{varName}` внутри `condition`** — не работает. Только `context.varName`.
2. **Инлайновые флаги regex `(?i)`** — ломают сценарий. Используй `/.../i`.
3. **`transitions` у `condition`-узла** — у него только `trueTarget`/`falseTarget`.
4. **Битый `targetNodeId`** — ссылка на несуществующий узел. Все цели должны быть в `states`.
5. **Нет `start` или `end`** — сценарий невалиден.
6. **Fallback с низким приоритетом** — `".*"` с `priority: 1` перехватит всё раньше конкретных.
   Fallback всегда `>= 100`.
7. **Не объявлены переменные** в `config.context` — объявляй все, что используешь.
8. **Нет обработки невалидного ввода** на узлах-вопросах — ставь `enableErrorHandling: true`,
   `invalidInputMessage`, `maxInvalidAttempts`, `invalidAttemptsTargetNodeId`.
9. **Забыл `unconditional: true`** после служебных узлов (`http`/`notify_user`/`action`/
   `schedule_message`/`clear_scheduled_messages`) — сценарий «зависнет» в ожидании ввода.
10. **Числа из ответов сравниваются как строки** — оборачивай `parseInt(context.x)`.
